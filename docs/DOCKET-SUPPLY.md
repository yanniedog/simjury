# Docket supply — keeping a rolling seven days queued

The Daily Docket promises a new case every day. This is how that promise is
kept, what "complete" means for a case, and what the drafting agent owns.

`ROADMAP.md` makes case supply priority one. This file is the operational
contract behind it.

## The loop

`.github/workflows/docket-supply.yml` runs every morning at 18:10 UTC.

1. **Measure.** `scripts/docket-supply.ts` lists which of the next seven days,
   including today,
   open no case. It names dates rather than a quantity, because "commission
   three cases" says nothing about when they publish, and three filed on one day
   leave the docket exactly as thin as before.
2. **Commission.** If any day is empty it raises — or updates — a single
   `docket-supply` issue naming those dates. One issue, edited daily, so a
   persistent shortfall does not become a wall of duplicates.
3. **Draft.** A case is written for each date against
   [`docs/DAILY-PROMPT-PACK.md`](DAILY-PROMPT-PACK.md) and
   [`docs/DAILY-CASES.md`](DAILY-CASES.md).
4. **Complete it.** Narration and images are produced before the case is
   proposed. See *What complete means* below.
5. **Prove it.** `npm run validate:cases` must pass.
6. **Propose it.** The case arrives as a pull request and goes through the
   ordinary gates. **Never written to `main` unattended.**
7. **Close.** Once the rolling week is covered the workflow closes the issue.

`validate:cases` also prints coverage on every run, so the gap is visible in any
CI log rather than only in the scheduled job:

```text
docket coverage: 7/7 days open a new case — a new case every day
```

## Automated editorial ownership

The 2026-08-02 owner decision removes the mandatory human approval checkpoint.
The drafting agent owns story, legal clarity, language, sensitivity, media,
narration, verification and review-feedback fixes. A second independent agent
pass challenges the case before its PR is marked ready. Record the real
agent/model in `gen_meta`; never invent a human reviewer.

The safety boundary remains firm: automation creates pull requests, never direct
`main` writes. Deterministic `validate`, `bot-feedback-gate`, and resolved review
threads remain the merge bar.

## What complete means

A case is not shippable until all three exist. Half a case in the docket is
worse than an honest gap, because the gap is at least visible.

### Text

Passes `npm run validate:cases`, which enforces the schema, design quality,
jury floors, deliberation dynamics, the banned-token scan, queue rules, and the
computed 19–21 minute sitting. Authors cannot declare a duration; it is computed
from content.

Every case carries `label: "fiction"` and contains no real names of people,
companies, brands or places in player-visible text. Cases are built from real
trial *patterns*, never real events.

### Audio

Generated by the existing Kokoro pipeline
(`.github/workflows/natural-narration.yml`), which already gives every speaker a
distinct, appropriate voice:

- **Narrator** — `af_heart`, reserved and never reassigned to a courtroom speaker.
- **Judge** — `bm_george` or `bf_emma`, reserved for gravitas.
- **Everyone else** — walked through a gender-matched pool so speakers stay as
  distinct as the catalogue allows, with `castGenders.json` fixing each
  speaker's gender so a voice cannot drift between runs.

Narration is generated in CI, never synthesised during play. Clip ids fold the
chosen voice, so a remap stays corpus-safe.

### Images

Art direction is in [`site/app/docket/MEDIA-GUIDE.md`](../site/app/docket/MEDIA-GUIDE.md).
The required set per case:

| Asset | Purpose |
| --- | --- |
| `cover.webp` | Contemporary court sketch from the juror's viewpoint. Establishes the accused as a specific person without signalling innocence or guilt. |
| `characters/` | A "before the case" portrait grounded in an authored life detail, plus the complainant or opposing witness, so both sides have equal humanity. |
| Selected beats | Only where an image changes how a juror understands the record. Not one per paragraph. |

Court images are charcoal and ink with selective watercolour and contemporary
dress — no wigs, gavels, or sepia. Evidence images preserve the ambiguity the
jury meets them with.

## Provider and checked-in defaults

The scheduled controller uses the repository's existing `GEMINI_API_KEY` with
checked-in Google Gemini models and conservative hard caps. No case-generation
variables or GitHub App are required. The built-in `GITHUB_TOKEN` creates the
draft PR, then explicitly dispatches required CI, the thread gate and advisory
review requests because token-authored GitHub events do not recurse.

- **Drafting.** `gemini-3.5-flash` drafts; `gemini-3.1-pro-preview` performs the
  independent story pass; `gemini-2.5-pro` performs the final independent legal
  pass over that revised bundle. Rejected JSON, structure, hashes or checklists are
  re-prompted within the two-attempt cap with the trusted validation error.
- **Images.** `gemini-3.1-flash-image` produces every declared portrait, cover
  and selected beat image. Trusted `ffmpeg` converts provider bytes to bounded
  WebP assets before the existing media validator accepts them.

If the key is absent, lacks paid image access, exceeds the USD cap, or any model
or validator rejects a sitting, the issue records the blocker and no partial
case is published.

## Autonomous drafting configuration

The workflow pins these values in source and runs with the existing secret:

| Kind | Names |
| --- | --- |
| Secret | `GEMINI_API_KEY` |
| Provider | trusted in-workflow Gemini adapter and the three distinct models above |
| Hard caps | 2 generation attempts, 2 repair attempts, 24 images, 12 MB, USD 8 and 64,000 output tokens per case |

The three model ids remain distinct. The workflow grants its short-lived
repository token only contents, issues, pull requests and Actions write access.

The adapter implements `simjury.case-agent/v1`. It receives the exact
UTC dates, reserved draft-PR number, authority documents, phase, pinned model and
remaining caps. It returns only regular files plus actual model, cost and review
metadata. The controller permits docket JSON and case WebP assets only, rejects
path traversal, symlinks, executable-style JSON fields and unbounded output, and
writes nothing until both independent passes approve. Kokoro narration is then
generated by the existing trusted pipeline, not by the authoring provider.

The daily issue is the durable machine record. Missing configuration sets
`blocked_configuration` and names the absent values. A run reserves a draft PR
before generation, records state in `.automation/docket-case-generation.json`,
and can resume idempotently. Review events repair and disposition unresolved
threads up to the configured cap. Each generation or repair attempt runs the
complete deterministic app merge bar and invokes `pr:arm-and-park` once; it never
waits or polls for reviewers.

## Guardrails this must never cross

- **No runtime AI.** Generation happens in PRs. Player-facing text is
  pre-authored JSON by the time anyone plays it.
- **No direct writes to `main`.** Generated work lands through required PR gates.
- **No real names**, and `label: "fiction"` on every case.
- **No case without its media.** Text, audio and images ship together.
